# 待确认决策

本文同时记录已确认决策与后续批次前才需要讨论的问题。

## D-001 技术栈与首发平台【已确认】

- Godot 4.6.1，GDScript。
- 首版面向 macOS/Windows 横屏桌面端，键鼠优先。
- 1600×900 为设计基准，同时验证 1280×720。
- 移动端、触屏和完整手柄支持不进入 Vertical Slice。

## D-002 永久死亡与读档策略【已确认】

- 三个手动存档槽加一个自动档。
- 玩家允许读取旧档；永久死亡只对当前时间线永久。
- 手动保存仅限主城和远征节点之间。
- 战斗中不保存完整回合状态；退出后以相同 Seed 从本战开头恢复。
- 自动保存发生在新建战役、节点结算后和远征最终结算后。

## D-003 玩家角色在 Vertical Slice 中的范围【已确认】

- 自创玩家角色在主城与武将界面可见，但暂不可出征。
- 首轮专注赵烈、周靖、韩月三种 Build。
- UI 必须明确这是 Vertical Slice 原型限制，不改变正式版允许玩家亲征的锁定规则。

## D-004 首轮视觉与交互目标【已确认】

- 采用“人物/军阵氛围 + 桌面卡牌”的混合表现。
- 信息层级可参考《杀戮尖塔》，但不复制其美术资产。
- 优先保证中文卡牌文本、Intent、士气、兵种构成和条件提示可读。
- M2 使用原创占位背景与武将剪影，不等待正式美术。

## D-005 河源县地图生成方式【已确认】

- 采用“固定战略骨架 + Seed 随机普通节点”。
- 三条路线、三个战略据点、汇合精英与 Boss 位置固定。
- 普通战、事件、补给、情报和财富节点在约束内变化。

## D-006 设计规格补齐责任【已确认】

M1 内核成型后，由 Codex 按已锁定机制提交“19 张卡 + 三武将初始牌组 + 敌人技能”原型规格草案。用户确认后再进入 M3 内容实现；草案数值全部标为【原型暂定】。
