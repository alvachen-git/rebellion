# 待确认决策

下面只列会改变近期实现方向的问题。卡牌数值、地图权重等可以在对应里程碑前再讨论。

## D-001 技术栈与首发平台（阻塞 M0 工程骨架）

建议默认方案：Godot 4.x，先做 macOS/Windows 横屏桌面版，键鼠优先，并从一开始保留手柄导航所需的焦点结构。

需要确认：

- 是否采用 Godot 4.x？
- 首发只做桌面端，还是第一版就要求移动端/触屏？

## D-002 永久死亡与读档策略（阻塞存档和死亡结算）

“永久死亡”是否需要系统层防止读旧档规避？可选方向：

1. 铁人模式：关键节点自动保存，死亡与不可逆升级立即落盘，只有一个进行中存档。
2. 普通模式：允许手动存/读档，永久死亡仅指当前时间线中的状态。
3. 两种模式都做：更灵活，但会扩大 Vertical Slice 的存档与 UI 范围。

建议首个 Vertical Slice 先实现单存档铁人逻辑，同时提供开发专用备份和调试重置；否则永久死亡的压力容易被读档完全消解。

## D-003 玩家角色在 Vertical Slice 中的范围

两种合理范围：

1. 玩家角色可完整亲征，另有赵烈/周靖/韩月三名测试武将；需要补一套玩家角色基础天赋/牌组规则。
2. 玩家角色先作为可见但不承担 Build 验证的基础占位，首轮只用三名测试武将远征；更快验证核心战斗。

建议先选第 2 项，但必须在界面上明确这是原型限制，不能让玩家误以为正式规则禁止亲征。

## D-004 首轮视觉与交互目标（阻塞 M2，不阻塞 M1）

建议默认：16:9 横屏，首测 1600×900 与 1280×720；战斗信息布局以“人物/军阵氛围 + 清晰桌面卡牌”为主，优先保证长中文文本、Intent 与条件提示可读。

需要确认：

- 更偏人物立绘叙事，还是更偏军阵/战场态势？
- 是否已有明确美术参考、字体或色彩方向？

## D-005 河源县地图生成方式（M4 前确认）

建议采用“固定战略骨架 + Seed 随机普通节点”：三条路线、三个战略据点、汇合精英与 Boss 位置固定，普通战/事件/补给的具体组合在约束内变化。这样既能保证 Boss 路线设计，又保留重玩差异。
