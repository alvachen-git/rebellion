# 待确认决策

本文同时记录已确认决策与后续批次前才需要讨论的问题。

## D-001 技术栈与首发平台【已确认】

- Godot 4.6.1，GDScript。
- 首版面向 macOS/Windows 横屏桌面端，键鼠优先。
- 1600×900 为设计基准，同时验证 1280×720。
- 移动端、触屏和完整手柄支持不进入 Vertical Slice。

## D-002 永久死亡与读档策略【已确认】

- 三个手动存档槽加一个自动档。
- 玩家允许读取旧档；永久死亡只对当前时间线永久。
- 手动保存仅限主城和远征节点之间。
- 战斗中不保存完整回合状态；退出后以相同 Seed 从本战开头恢复。
- 自动保存发生在新建战役、节点结算后和远征最终结算后。

## D-003 玩家角色在 Vertical Slice 中的范围【已确认】

- 自创玩家角色在主城与武将界面可见，但暂不可出征。
- 首轮专注赵烈、周靖、韩月三种 Build。
- UI 必须明确这是 Vertical Slice 原型限制，不改变正式版允许玩家亲征的锁定规则。

## D-004 首轮视觉与交互目标【已确认】

- 采用“人物/军阵氛围 + 桌面卡牌”的混合表现。
- 信息层级可参考《杀戮尖塔》，但不复制其美术资产。
- 优先保证中文卡牌文本、Intent、士气、兵种构成和条件提示可读。
- M2 使用原创占位背景与武将剪影，不等待正式美术。

## D-005 河源县地图生成方式【已确认】

- 采用“固定战略骨架 + Seed 随机普通节点”。
- 三条路线、三个战略据点、汇合精英与 Boss 位置固定。
- 普通战、事件、补给、情报和财富节点在约束内变化。

## D-006 设计规格补齐责任【已确认】

M1 内核成型后，由 Codex 按已锁定机制提交“19 张卡 + 三武将初始牌组 + 敌人技能”原型规格草案。用户确认后再进入 M3 内容实现；草案数值全部标为【原型暂定】。

## D-007 M3 敌人软克制边界【已实现，数值待试玩】

- 敌人使用技能池、公开 Intent、权重、条件与冷却，不建立敌方完整牌组，也不读取玩家未来手牌。
- 五种普通敌人只通过属性与技能节奏形成考题，不对任何 Build 提供硬免疫。
- 高武【军纪严整】只将每个玩家回合第一次士气损失减半并向下取整，同回合后续士气损失正常生效。
- 贺巍【黑甲】只在初始护甲被玩家打穿时触发；下一次 Intent 选择排除防守，随后技能池恢复。初始护甲自然到期或后来获得的普通护甲不会触发。
- 上述属性、权重、冷却和数值继续保持【原型暂定】，M3-05 统计前不视为最终平衡结论。

## D-008 严成阶段与战略削弱边界【已实现，数值待试玩】

- 【死守孤城】只在严成兵力首次从50%或以上降至50%以下时触发；恰好50%不触发，每战最多一次。
- 触发时立即获得阶段护甲并进入第二阶段，但不替换本回合已经公开的 Intent；【固守城池】排入下一次敌方行动。
- 【求援烽火】与阶段强制行动共用先进先出队列；若同一玩家回合先后入队，则按入队顺序逐回合执行，之后恢复普通技能池。
- `armory_destroyed`、`beacon_destroyed`、`granary_destroyed` 只作为 CombatRequest 的战前输入，由纯函数应用于战斗定义副本；不写回共享内容数据，也不在 Combat 内判断地图完成状态。
- Boss 属性、阶段护甲、技能权重、冷却与削弱幅度继续保持【原型暂定】，M3-05 统计前不视为最终平衡结论。

## D-009 M3 回合目标适用口径【平衡延期】

- 首轮固定策略以三 Build × 八敌人 × Seed 1～20运行480场；结果为455胜、0负、25场达到20回合上限，只有8/24个组合的平均回合位于层级目标。
- 同一严成 Boss 上，赵烈平均5.60回合、韩月14.55回合、周靖20场全部超时；直接统一增加或减少 Boss 兵力无法同时修复三者。
- 玩家决定先继续搭建游戏框架，平衡调整延后；普通3～5、精英4～7、Boss 6～10继续作为未达成的设计基准，不因延期而视为通过。
- 延期期间不改变卡牌、武将、敌人或 Boss 的【原型暂定】数值；恢复调参时仍需确认目标适用口径，并保留修改前后480场对照。

## D-010 河源县节点数量口径【框架暂定，待流程试玩】

- 当前将“12～16节点”实现为整张分叉图的总节点数：河源县共15节点，一条完整路线经过7节点（含起点与 Boss）。
- 三条前段路线、战略据点、汇合精英、后三选一与 Boss 均为固定骨架；只有六个普通槽的类型由 Seed 在受控列表内解析。
- 这一解释不锁定最终远征时长。M4 UI 和连续战斗串联后，如7节点不足以支撑约30分钟目标，应先讨论增加纵向层数还是提高单节点内容密度。

## D-011 M5 远征结算分批落地边界【已实现】

- M5-01 只立即提交银钱、粮草、兵员、军学与特殊资源；成功才能获得奖励，撤退和失败不入库未结算战利品。
- 兵力/士气余量、重伤、死亡与任务结果先作为 `pending_long_term_effects` 写入 CampaignState，不在缺少军队、武将和领地模型时提前解释。
- 同一 `request_id` 只允许提交一次；请求必须先完成全量校验，再对深拷贝状态修改并整体替换，任一非法字段都不得产生部分入账。
- 该分批边界不改变玩法规则。M5-02、M5-04、M5-05 分别实现对应模型后，再以事务方式消费队列，并由 M5-07 覆盖中断恢复和旧档迁移。

## D-012 M5-02 军队经济与正式主城 UI 时点【已确认】

- Vertical Slice 的长期军队库存只包含步兵、弓兵、骑兵，属于势力统一库存，不建立武将私人部曲或独立场上单位。
- 补兵与兵种训练在领域层使用同一“按兵种配方补充库存”事务；每笔指令有稳定 `action_id`，必须全量校验资源后一次提交。
- 配方数值集中在 `data/config/prototype_army_economy.json`，并强制标记 `prototype_temporary`。这些数值只用于证明资源扣除、特殊材料门槛和存档流程，平衡以后再做。
- 新远征结算携带初始兵力与开战构成，按锁定构成分摊总伤亡并扣除统一库存；旧 DTO 缺少这两个字段时保持可读，但明确记录尚未应用分类伤亡。
- 玩家确认正式主城 UI 以后再做。本阶段不增加临时主城页面；先完成 M5-02～05 领域框架，M5-06 再制作正式入口与出征整备 UI，M6 串联完整流程。

## D-013 M5-03 公共研究与永久升级边界【已实现，经济待平衡】

- M3 的16张 `owner_scope=public` 卡进入势力研究目录；赵烈、周靖、韩月的武将专属卡不进入公共研究，也不允许通过公共升级事务修改。
- 解锁消耗银钱与军学，部分稀有研究可额外要求兵法残篇等特殊资源；费用与残篇门槛集中在 `prototype_research_economy.json` 并强制标记 `prototype_temporary`，以后再做平衡。
- 解锁和升级各自使用稳定 `action_id` 幂等提交。任何资源、卡牌或分支校验失败都不得产生部分扣费、部分解锁或半个升级状态。
- 每张已解锁公共卡最多选择一个升级分支；一旦写入 `card_upgrade_branches`，同局不允许覆盖、重置或洗点。
- 运行时不修改共享卡牌定义，而是从基础定义深拷贝并应用已锁定分支。正式出征整备在 M5-06 接入此解析接口。
- 新战役默认公共牌库尚未决定。M5-03 保持空状态，不把测试武将当前调试牌组误当作正式长期解锁进度；该选择在 M6 闭环前讨论。

## D-014 M5-04 武将成长与伤亡结算边界【已实现，内容与数值待设计】

- `GeneralInstance` 只保存武勇、统率、政务三项长期属性；固定核心天赋、当前可用天赋、专属卡、经验、等级、伤势和死亡状态分开保存。
- Vertical Slice 固定 Lv1～Lv6，且每次远征最多提升一级。经验阈值、结果经验、Lv2/Lv5 属性增量与重伤恢复周期集中在 `prototype_general_progression.json`，强制标记 `prototype_temporary`，以后统一平衡。
- 当前三名武将只有各一张已实现的 M3 专属卡，成长天赋分支和额外专属卡尚无规格。Lv3/Lv4/Lv6 只记录 `content_pending` 里程碑，不擅自创建正式分支、效果或卡牌。
- Combat 已经判定好的死亡/重伤结果由 Campaign 原样消费，不在长期层重抽。重伤阻止出征并由幂等势力周期事务恢复；具体两周期只是原型配置值。
- 死亡会清空当前可用天赋和专属卡；丢失 ID 仅保存在不可用于玩法的审计记录中。普通武将死亡不结束战役，玩家角色死亡立即写入 Game Over 并封锁后续长期操作。
- 自创角色仍遵循 D-003：本批只证明其死亡边界，`vertical_slice_deployment_enabled=false`，不加入首轮赵烈、周靖、韩月出征目录。

## D-015 M5-05 河源县与势力周期边界【框架已实现，时间策略待完整流程复核】

- 河源县作为第一块 `TerritoryInstance`，只保存稳定 ID、取得周期、来源请求和收入启用状态；收入来自 `TerritoryDefinition`，不复制进存档。其他城市继续只作为资产，禁止独立城市画面与逐城升级。
- 河源县原型周期收入采用设计表：银钱180、粮食260、兵员60、精铁8；主资源与特殊资源分别入账，并强制保持 `prototype_temporary`。
- 设计文档未确认撤退/失败是否推进势力周期。Vertical Slice 暂采用“只有主要远征成功才推进”的策略，避免立刻撤退反复刷收入；撤退、失败和非主要远征结果只消费势力效果并记录跳过原因。
- 首次攻取河源县推进到周期1并把主城从 `ruined_camp` 提升为 `rebel_camp`，但新领地在取得周期不立即发放收入；从下一次成功推进周期开始贡献。该收入时点属于原型策略，M6 完整流程试玩后复核。
- 每次实际推进周期时，在同一事务内汇总全部合格领地收入并推进重伤恢复；未知领地、非法收入或完整状态校验失败时，周期、收入、领地、恢复和流水全部回滚。
- 招贤刷新与世界阶段变化仍为【待设计】消费者，本批只在配置中显式标为 deferred，不制作无规则的占位结果。

## D-016 M5-07 存档迁移与旧结算恢复边界【已实现】

- 存档正式提升为 Save V2；V1 通过唯一迁移注册表按 `v1 → v2` 顺序升级，并保留原 `content_version` 与时间戳用于审计。未来版本和迁移后不满足完整 CampaignState 契约的文件必须明确拒绝。
- 每次保存先编码校验并写 `.tmp`，重新读取验证后才轮换正式档；只保留一份最近 `.bak`。主档结构损坏或内容稳定 ID 失效时可以读最近备份，但载入过程不自动覆盖损坏主档。
- 军队、武将、势力三个消费者由 `request_id` 最终化事务收口；已完成的消费者在中断恢复时不重复执行，后续消费者失败则回滚本次最终化中的全部变化。玩家死亡先提交 Game Over，同一请求的势力时间显式跳过。
- 旧 DTO 缺少初始兵力和构成时继续标记未应用兵损，禁止静默推测。玩家/流程显式选择兼容恢复后，军队库存不变，并保存 `legacy_snapshot_unavailable` 原因与审计；此策略只服务旧开发档，新 V2 结算仍必须真实分类扣损。
- 自动保存事件固定为新建战役、远征节点结算后和远征最终结算后；战斗回合不保存完整状态。正式槽位 UI 与旧档恢复提示仍按玩家要求后置。

## D-017 M6-01A 无 UI 闭环、Loadout 与检查点边界【已实现】

- 玩家确认先实现无 UI 流程：`新档 → 初始化 → 主城 → 出征整备 → 远征节点 → 战斗 → 最终结算 → 主城 → 再次出征`。河源县成功后只验证再次整备合法，不重跑同一任务，也不新增第二远征。
- 长期 Loadout 从本批进入 Campaign，固定20张并校验公共解锁、专属归属/解锁、复制上限和武将存活状态。新档解锁现有三套模板共同使用的15张公共卡；【追亡逐北】保持锁定。
- Save 提升为 V3。V2→V3 只补空 Loadout 结构，不静默授牌；旧档必须显式执行可审计、幂等的 Loadout 恢复。新档内容版本为 `0.6.0-m6-flow`，迁移档保留来源 `content_version`。
- 战斗节点创建不可变 CombatRequest 后自动保存；CombatResult 通过 `battle_id` 绑定当前战斗。恢复从战斗开头重建，不保存或恢复战斗中间回合。
- 终止战斗与最终结算分为两个持久化阶段。任何自动保存失败都回滚本次内存事务；最终保存失败继续停在 `settlement_pending`，不得进入主城。
- 河源县敌人池、奖励、事件、补给、情报及战斗 Seed 派生采用集中【原型暂定】配置。相同远征 Seed 与节点稳定复现；节点奖励、Buff、情报、据点削弱和路线完成用稳定 `resolution_id` 原子结算。
- 相对初始属性的原型换算为：每1武勇增加1攻击，每1统率增加0.5防御和25带兵上限，政务暂不影响战斗，士气沿用静态定义。该组数值只用于闭环试玩，未转为锁定平衡规则。
- M5-05 的“仅主要远征成功推进势力周期”和“新领地延迟一期收入”继续保持，不因 M6-01A 技术闭环自动转为正式规则；待玩家可见完整试玩后复核。

## D-018 M6-01B 正式试玩界面边界【已实现】

- 主场景改为 `GameShell`，但 UI 只编排 `GameFlowCoordinator`，不复制 Combat、Expedition 或 Campaign 规则。
- 第一版主城把整军、军学、武将、势力和出征压缩到同一工作区；招贤继续保持【待设计】，不制作无数据的入口。
- 牌组界面本批只支持闭环所需的【追亡逐北】加入动作，不把这一快捷操作冒充完整自由牌组编辑器；正式编辑器另行设计。
- 河源县地图依据内容节点和边生成，只把当前 `available_next_node_ids` 设为可操作；未知节点不显示真实类型、敌人或奖励。
- 战斗场景保留独立内容调试模式，同时增加远征集成模式；玩家确认战果后才提交 CombatResult，关闭游戏则从战斗检查点开头恢复。
- 视觉采用程序绘制的深墨远山、残阳与旗阵作为可替换原型资产。正式人物、城寨和事件美术仍未制作，不因当前界面可用而视为美术完成。
- M6-02 继续验证成功、撤退、失败、永久死亡和旧档恢复的玩家体验；M6-01B 自动化通过不代表第26节12个试玩问题已经获得玩家结论。

## D-019 M6-02 失败终报与旧档恢复体验边界【已实现】

- 失败页只解释 CombatResult 和 Expedition/Campaign 已确定的结果，不在 UI 重抽死亡、重伤或奖励。
- 撤退、士气失败和兵力归零使用不同原因文本；永久后果在最终确认前展示，避免玩家确认后才知道战利品、兵损、领地和周期结果。
- 普通武将永久死亡后回城并禁用该武将；只有 `campaign_status=game_over` 才进入 Game Over 页面。
- Save V2 缺 Loadout 时必须进入显式恢复页。恢复内容、审计和幂等规则沿用 D-017；UI 额外保存到手动槽1，但不得覆盖旧自动档。
- 起始页只显示实际存在的手动槽入口，不伪造空槽内容；自动档与手动槽载入共用同一 `load_campaign()` 校验和备份回退。
- M6-02 自动化证明状态、恢复和后果表达正确；设计文档第26节关于好玩、疲劳、风险感和Build差异的问题仍必须由 M6-03 真人试玩回答。
