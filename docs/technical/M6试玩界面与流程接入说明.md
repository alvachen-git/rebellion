# M6-01B 试玩界面与流程接入说明

> M6-03A 已新增独立“军议堂 · 牌组编排”，移除单卡快捷替换，并将出征整备更新为“共用基础牌组 + 所选武将全部专属牌”。本文件保留 M6-01B/02 的历史验收记录，当前规则与数据见《M6军议堂与共用基础牌组说明》与 D-020。

## 1. 交付结果

主场景已从独立战斗原型切换为 `GameShell`，玩家可以不使用调试命令完成：

`建立新军 → 主城 → 出征整备 → 河源县行军图 → 战斗 → 最终结算 → 主城成长 → 再次出征就绪`。

本批没有改变 Combat、Expedition 或 Campaign 规则；所有按钮都调用 M6-01A 的 `GameFlowCoordinator`。独立 `CombatScreen` 继续保留战前 Build/敌人选择模式用于 M2/M3 回归，在完整流程中使用集成模式和不可变 CombatRequest。

## 2. 界面阶段

- 起始页：建立新军；存在有效自动档或备份时可以继续战役。
- 主城：显示资源、军队库存、三名武将、长期牌组、势力周期和领地；提供补兵、研究、永久升级、牌组替换、手动保存和出征入口。
- 出征整备：选择赵烈、周靖或韩月，显示并允许调整三兵种数量；合法性完全来自 `expedition_readiness()`。
- 远征地图：按权威节点和边生成河源县路线；只开放当前合法节点，未知节点不泄露内容。
- 战斗：复用现有战斗 UI；结果必须由玩家确认后才提交远征节点。
- 最终结算：明确展示成功、撤退或失败以及战利品/损失；确认后才修改长期状态并回城。
- Game Over：以 Campaign 的 `campaign_status` 为唯一权威，不在 UI 自行判断死亡规则。

## 3. 视觉与交互

视觉采用深墨军帐、远山、残阳和旗阵的程序绘制背景；旧纸色承载正文，朱砂只强调当前主行动。主城使用三列工作区，地图用一张完整军报而不是卡片矩阵。

界面阶段使用短淡入；地图节点按列依次显现；战斗继续沿用手牌进入、悬停和敌军行动反馈。图形化截图复核后，提高了地图底板、路线、可选节点、已完成节点和未知节点的对比度。

设计画布保持1600×900，并通过 `canvas_items` 适配1280×720。自动化在两个目标分辨率检查关键行动没有越界；图形化捕获实际输出为1280×720。

## 4. 保存与恢复

起始页的“继续战役”读取自动档；主档损坏时仍沿用 SaveFileStore 的最近备份回退。地图节点、战斗检查点、终态检查点和最终结算的保存时点没有改变。

战斗结果遮罩尚未确认时关闭游戏，恢复后会从该场战斗开头重建，而不是恢复战斗中间回合。主城补兵、研究和牌组修改仍需手动保存，或等待下一次战斗检查点写入自动档。

## 5. 自动化证据

`tests/run_m6_ui_tests.gd` 通过真实控件信号覆盖新档、主城、三武将整备、地图节点、首战真实出牌与结束回合、战斗检查点重启、完整成功路线、最终结算、领地显示、补骑兵、解锁【追亡逐北】、升级【突击】、修改长期牌组、手动保存和再次出征就绪，共39项断言。

M6 UI 专项为39通过、0失败；包含 M6-01A/01B 的20组串行全量回归为1686通过、0失败。严格错误标记扫描没有解析错误、无效调用、未处理异常或测试失败；仅保留脚本精确白名单中的 Godot 4.6.1 macOS CA 证书噪声。

## 6. M6-02 失败与恢复接入

失败终报新增结果原因与长期后果：撤退强调生还与战利品丢失；士气失败明确军心崩溃和重伤；兵力归零明确武将永久死亡。玩家角色死亡存档恢复到独立 Game Over 页面。

Save V2 缺少长期 Loadout 时不进入不完整主城，而是显示显式恢复页，列明15张公共卡和三套20张牌组的授予内容。恢复结果写入手动槽1，原自动档保持不变；起始页可以直接载入已有手动槽。

M6-02 体验专项为33通过、0失败；21组完整回归为1719通过、0失败。后续 M6-03A 已完成共用基础牌组与军议堂编辑器；当前下一步为 M6-03B 真人12问试玩。招贤、正式人物美术、事件多选和更多远征仍不在范围。
