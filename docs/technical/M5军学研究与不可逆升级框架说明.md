# M5 军学研究与不可逆升级框架说明

## 1. 本批范围

M5-03 实现势力公共卡的长期研究、永久解锁和一次性二选一升级。正式军学页面仍留在 M5-06；本批交付数据目录、Campaign 事务、保存状态和供以后出征组牌调用的卡牌分支解析接口。

研究目录包含 M3 的16张公共牌，不包含三张武将专属牌。新战役默认开放哪些公共牌尚未确定，因此 CampaignState 保持空解锁列表，不把当前战斗调试牌组偷偷固化成长期进度。

## 2. 长期状态

- `unlocked_public_cards`：已永久解锁的公共卡 ID，必须唯一。
- `card_upgrade_branches`：`card_id → branch_id` 的唯一永久选择；只有已解锁卡才能出现。
- `research.applied_action_ids`：已提交研究操作的幂等账本。
- `research.history`：解锁/升级、卡牌、分支和实际成本的审计流水。

旧 V1 的空 `research` 对象会补上两个空数组；重复卡 ID、未解锁卡的升级或空分支 ID 会在 CampaignState 校验时被拒绝。

## 3. 原型研究经济

`data/config/prototype_research_economy.json` 集中保存：

- 16张可研究公共卡 ID。
- 基础、高级、稀有、秘策四档解锁成本。
- 四档升级成本。
- 个别卡牌的特殊研究材料；当前以【追亡逐北】需要 `resource.cavalry_fragment` 验证兵法残篇门槛。

配置必须标记 `balance_status=prototype_temporary`。当前银钱、军学与残篇数量只用于证明事务流程和资源选择，不是最终经济平衡。

## 4. 解锁事务

`unlock_public_card()` 接收稳定 `action_id` 与 `card_id`：

1. 卡牌必须存在于已验证的公共研究目录，武将专属牌直接拒绝。
2. 已解锁卡不能用新操作再次研究。
3. 银钱、军学和可选特殊资源必须全部满足。
4. 在深拷贝 CampaignState 上一次扣费、添加解锁、登记幂等 ID 与流水。
5. 同一 `action_id` 重放返回成功重复态，但不会重复扣费。

## 5. 不可逆二选一

`upgrade_public_card()` 只接受已经解锁且尚未升级的公共卡。分支 ID 必须来自该卡两个结构化 `upgrade_branches` 之一。

第一次合法选择会一次扣除升级成本并写入 `card_upgrade_branches`。之后无论选择相同或另一分支，只要使用不同操作 ID 都会被拒绝；没有重置、覆盖或洗点接口。

`resolved_public_card()` 从 ContentRegistry 的基础卡深拷贝，再应用已保存分支的 `overrides`，并标记 `applied_upgrade_branch`。它不会修改共享卡牌内容，因此不同存档、战斗和测试不会串状态。M5-06 的正式出征组牌应调用这个接口。

## 6. 自动化证据

`tests/run_m5_research_tests.gd` 覆盖旧档增量状态、16张公共牌目录、专属牌拒绝、原型费用、特殊残篇、解锁/升级幂等、资源回滚、未知分支、永久锁定、禁止洗点、运行时深拷贝和存档往返，共86项断言。

M5-03 完成后的15组串行回归为1167通过、0失败；额外错误扫描未发现 `SCRIPT ERROR`、`Parse Error`、`Invalid call`、`TEST FAIL` 或非已知 macOS CA 噪声的 `ERROR:`。
