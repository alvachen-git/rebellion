# M4 远征地图框架说明

## 当前范围

M4-01/02 已完成《攻取河源县》的内容定义、Seed 生成、节点图、前进约束和迷雾运行态。本批只回答“地图是什么、下一步能去哪里、玩家当前知道什么”，不提前处理节点奖励、跨战兵力/士气、临时 Buff、战利品袋或最终结算。

## 河源县骨架

完整图包含15个节点、18条有向边：

`义军营地 → 官道/村野/粮道各两格随机槽 → 军械库/烽火台/粮仓 → 汇合精英 → 情报/补给/财富三选一 → 河源县城 Boss`

- 官道固定通往军械库，对应 `armory_destroyed`。
- 村野固定通往烽火台，对应 `beacon_destroyed`。
- 粮道固定通往粮仓，对应 `granary_destroyed`。
- 三条前段路线必须汇合到精英节点；后三选一都必须进入严成 Boss。
- 当前将“12～16节点”解释为完整分叉图总节点数；一条完整路线经过7个节点（含起点与 Boss）。这个流程长度仍需在 M4 UI 串联后按实际时长试玩确认。

## 内容契约

远征定义由 `ContentRegistry` 从 `data/content/expeditions/` 加载。校验包括：

- 稳定且唯一的远征/节点 ID，节点数量必须位于定义范围。
- 节点类型必须属于首轮白名单；固定类型与随机类型槽只能二选一。
- 起点和 Boss 引用有效，Boss 节点必须提供已注册敌人 ID。
- 所有边必须引用已知节点并严格前进到更高列，因此数据层不能形成回边或环。
- 所有节点必须从起点可达，三条战略路线必须绑定正确的军事节点和 Boss 修正。

随机槽的 `node_type_options` 是集中数据中的【原型暂定】路线倾向；重复项表示当前原型权重，不是最终概率。节点具体事件、奖励和敌人分配留在后续内容批次。

## Seed 生成

`ExpeditionMapGenerator` 深拷贝远征定义，使用隔离的确定性 RNG 解析普通节点槽。相同定义和 Seed 会得到完全相同的节点类型、边和战略目标；不同 Seed 只能改变随机槽，不能移动起点、据点、汇合精英、后三路线或 Boss。

生成结果同时提供节点数组、按 ID 索引和出边索引，供规则层和未来 UI 使用。共享的 ContentRegistry 定义不会被写入运行态。

## 路线与迷雾

`ExpeditionRouteState` 保存当前节点、已走节点、已完成节点、已揭示节点和运行状态。

- 起点自动完成，并揭示三条路线的第一个可达节点。
- 进入节点后必须先完成当前节点，才能选择它的出边。
- 只能进入当前节点的直接后继；不能跳点、跨线或返回已走节点。
- 完成节点时才揭示后继。被迷雾覆盖的节点对外只返回“未知节点”，不泄露类型、敌人或据点信息。
- 三个战略目标和最终 Boss 始终可见，使玩家能够进行有意义的路线规划。
- 完成 Boss 节点后路线状态变为 `completed`；成功/失败远征结算仍由后续 ExpeditionController 负责。

## 自动化入口

`tests/run_m4_map_tests.gd` 覆盖15节点契约、错误节点/边/类型/据点、同 Seed 复现、不同 Seed 变化、共享定义不变、固定战略骨架、迷雾揭示、逐节点推进、汇合/分叉、不可回头和 Boss 完成，共75项断言。加入该套件后的完整串行回归为708通过、0失败。
