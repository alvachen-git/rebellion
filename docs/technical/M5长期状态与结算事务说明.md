# M5 长期状态与结算事务说明

## 1. 本批范围

M5-01 建立远征与长期战役之间的第一个可执行边界，负责 CampaignState 基础结构、四项主资源、特殊资源分仓和 `ExpeditionSettlementRequest` 的幂等事务式接收。

本批不提前实现军队补兵/训练、武将成长/伤亡、军学研究/卡牌升级或领地周期。远征结果中属于这些系统的数据先进入稳定的待处理队列，后续批次再消费。

## 2. CampaignState

四项主资源使用固定键：

- `silver`：银钱
- `food`：粮草
- `recruits`：兵员
- `military_knowledge`：军学

非四主资源按稳定内容 ID 存入 `special_resources`，例如 `resource.refined_iron`。这样不会把后续特殊材料动态塞入固定主资源表，也不会要求代码为每种材料新增字段。

M5-01 新增三个增量字段：

- `applied_settlement_ids`：已应用的结算请求 ID，用于防止重复入账。
- `settlement_history`：最小审计流水，保存任务结果及实际资源变化。
- `pending_long_term_effects`：等待军队、武将和领地系统消费的长期结果。

M5-02 进一步把 `army_inventory` 固化为步兵、弓兵、骑兵三项统一库存，并增加 `applied_army_action_ids` 与 `army_history`，分别承担补兵指令幂等和长期军队操作审计。旧 V1 的空库存与缺失流水字段会增量补零/补空数组。

M5-03 将 `research` 规范为 `applied_action_ids` 与 `history` 两项事务状态；`unlocked_public_cards` 保存永久公共卡解锁，`card_upgrade_branches` 保存唯一分支。旧 V1 的空研究对象会增量补齐流水字段，不自动授予公共卡或选择升级。

M5-04 将 `generals` 固化为可校验的 `GeneralInstance` 列表，并增加 `general_system`、`campaign_status` 与 `game_over_record`。同一远征结果可由军队和武将系统分别消费：`army_losses_applied` 与 `general_effect_applied` 各自标记完成状态，互不伪装成整条长期效果已经全部结清。

M5-05 将 `territories` 固化为 `TerritoryInstance` 列表，并增加 `faction.applied_effect_ids`、`faction.history` 与 `faction_effect_applied`。河源县收入只从内容定义读取；势力周期、收入和重伤恢复在同一个深拷贝事务中提交。

## 3. 结算事务

CampaignController 按以下顺序接收远征结算：

1. 控制器必须已经用合法 CampaignState 初始化。
2. 全量校验必填字段、结果枚举、布尔标记、兵力/士气以及战利品数量。
3. 检查稳定 `request_id`；已应用请求返回成功但不再次修改状态。
4. 深拷贝当前 CampaignState，只在副本上计算资源、流水和待处理效果。
5. 所有计算完成后整体替换当前状态。

因此，一个请求中即使前一项战利品合法、后一项非法，也不会出现部分资源已经写入的状态。

## 4. 三类结果

- `success`：把 `loot_to_bank` 中的四主资源与特殊资源分别入库，并记录长期结果。
- `retreated`：禁止携带入库奖励，只记录已经发生的兵力/士气损失与丢弃战利品审计。
- `failed`：禁止携带入库奖励，保留战斗给出的死亡、重伤和剩余军队状态，等待后续系统处理。

Campaign 不保存 Expedition 运行对象，只保存结算 DTO 的必要长期结果，继续维持 Combat、Expedition、Campaign 三层隔离。

## 5. 旧存档兼容

已有 Save V1 缺少本批新增的三个字段。载入 CampaignController 时会为缺失字段补空数组，并为缺失的四主资源键补零；原存档中的其他长期状态保持不变。

JSON 数字解码后可能表现为浮点数，因此契约接受非负整数值及与整数等值的有限浮点数，但拒绝字符串、负数、无穷值和小数损耗。当前修改属于 V1 的增量兼容，不提升 `save_version`；若后续改变既有字段结构或语义，必须在 M5-07 建立显式迁移。
