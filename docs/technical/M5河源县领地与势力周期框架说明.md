# M5 河源县领地与势力周期框架说明

## 1. 本批范围

M5-05 建立第一块领地与势力周期的领域框架：成功完成《攻取河源县》后授予河源县、推进主城阶段和势力周期；后续周期统一结算领地收入与武将重伤恢复。

本批不制作正式势力/主城 UI，不实现招贤刷新、世界阶段事件或多城建设。其他城市始终只作为势力资产，不生成独立经营状态和页面。

## 2. TerritoryDefinition 与 TerritoryInstance

河源县定义位于 `data/content/territories/heyuan_county.json`，由 ContentRegistry 随其他正式内容加载并验证。定义包含：

- 稳定领地 ID 与来源远征 ID；
- 首次占领后的主城阶段；
- 四主资源与特殊资源分仓的周期收入；
- `independent_city_management=false`，禁止逐城经营；
- `balance_status=prototype_temporary`，明确收入尚未平衡。

CampaignState 中只保存运行时 `TerritoryInstance`：稳定 ID、名称、controlled 状态、是否启用收入、取得周期和来源结算请求。具体收入数值继续来自内容定义，避免把平衡数据复制进存档。

## 3. Vertical Slice 周期策略

设计文档没有最终确认主动撤退或失败是否推进势力周期。为避免玩家通过“开始远征后立刻撤退”反复刷领地收入，本批在 `prototype_faction_cycle.json` 中明确采用以下原型策略：

- 只有配置为主要远征的 `success` 结果推进1个势力周期；
- `retreated` 与 `failed` 会被消费和审计，但推进0周期、不给收入、不给重伤恢复；
- 非主要远征成功同样不推进周期；
- 新占领领地在取得周期不立即发放收入，从下一次成功推进周期开始贡献；
- 招贤刷新与世界阶段变化显式列为 deferred，不提供空实现伪装完成。

该策略属于 Vertical Slice 原型边界，不自动升级为完整战役的最终时间规则。

## 4. 河源县结算顺序

成功结算的势力事务按一个深拷贝原子提交：

1. 校验结算请求、结果、主要远征目录和幂等状态；
2. 将势力周期推进1；
3. 若尚未拥有河源县，则创建唯一 TerritoryInstance 并把主城从 `ruined_camp` 推进为 `rebel_camp`；
4. 汇总在目标周期已经满足收入延迟的领地；
5. 分别增加主资源与特殊资源；
6. 所有重伤武将推进1个恢复周期；
7. 写入势力与恢复审计，并标记共享长期效果已由势力系统消费；
8. 对完整 CampaignState 重新校验后整体替换。

任何未知领地定义或状态错误都会回滚领地授予、周期、收入、恢复与流水，不产生部分提交。

## 5. 幂等与旧档

`faction.applied_effect_ids` 以远征 `request_id` 防止重复占领、重复推进或重复收入；`faction.history` 保存推进或跳过原因。共享 `pending_long_term_effects` 增加 `faction_effect_applied`，使军队、武将、势力消费者能分别确认自己的完成状态。

旧 V1 存档缺少 `faction` 或新消费标记时增量补空流水与 `false`，不改变 `save_version`。周期、主城阶段、领地实例、收入、势力幂等流水和重伤恢复流水均覆盖 JSON 往返测试。
