# M5 武将成长、重伤与永久死亡框架说明

## 1. 本批范围

M5-04 把武将从内容定义转换为可长期保存的 `GeneralInstance`，并消费远征结算队列中的成长、重伤与死亡结果。本批只实现领域状态和事务接口，不制作正式武将/主城 UI，也不替 Combat 重抽死亡或重伤概率。

Combat 仍是风险结果的唯一判定者：兵力归零产生死亡；士气归零产生已经确定的死亡或重伤。Campaign 只按 `general_died` / `general_injured` 提交长期结果。

## 2. GeneralInstance

每名长期武将保存：

- 稳定 `general_id`、显示名和玩家角色标记；
- Lv1～Lv6、累计经验；
- 仅武勇、统率、政务三项长期属性；
- 固定核心天赋 ID、当前可用天赋 ID；
- 当前可用专属卡 ID；
- 待处理和已完成的成长里程碑；
- 健康/重伤及剩余恢复周期；
- active/deceased 状态与死亡审计记录。

自创玩家角色在 Vertical Slice 中仍是不可出征占位，`vertical_slice_deployment_enabled=false`。赵烈、周靖、韩月由正式内容定义初始化，当前 M3 已实现的第一张专属卡从 Lv1 起归属本人。

## 3. 原型成长配置

经验阈值、三类远征结果经验、Lv2/Lv5 少量属性增量和重伤恢复周期集中在 `data/config/prototype_general_progression.json`，配置必须保持 `balance_status=prototype_temporary`。

当前数值只证明成长、恢复、存档和事务路径，不作为平衡结论。代码强制：

- Vertical Slice 最高 Lv6；
- 一次远征最多提升一级，超额经验保留；
- Lv2/Lv5 只发生小幅三属性成长；
- Lv3/Lv6 记录天赋二选一里程碑；
- Lv4 记录新增专属卡里程碑。

三名武将的成长天赋分支与额外专属卡尚无设计规格，因此 Lv3/Lv4/Lv6 只写入 `status=content_pending` 的稳定里程碑，不虚构分支 ID、效果或卡牌。

## 4. 重伤、死亡与 Game Over

重伤会按原型配置写入剩余恢复周期，`general_availability()` 明确返回 `major_injury`，势力周期可通过幂等 `action_id` 调用恢复事务。M5-05 接入周期推进时复用该接口。

武将死亡后：

- 状态永久变为 `deceased`；
- 当前可用天赋和专属卡立即清空；
- 丢失内容只保存在不可用于出战的死亡审计记录中；
- 普通武将死亡不结束战役；
- 玩家角色死亡把 Campaign 原子地改为 `game_over`，并拒绝后续结算和恢复操作。

允许读取旧档只表示玩家可以回到旧时间线；当前时间线内没有复活、继承或转移专属体系的接口。

## 5. 事务与旧档

`general_system` 分别记录初始化、远征效果和恢复周期的幂等 ID，并保留统一历史。每条 `pending_long_term_effects` 增加 `general_effect_applied`，使军队、武将和后续领地消费者可以独立标记同一结算的消费状态。

旧 V1 Campaign 缺少新字段时增量补为 active、空流水和未消费效果；不提升 `save_version`。GeneralInstance、重伤剩余周期、死亡记录、Game Over 与所有幂等 ID 均通过 Save V1 JSON 往返测试。
