# M6 分岔汇合地图、民望与事件库说明

## 1. 当前规则边界

M6-04F 将新远征切换到 `generator_version=4`。地图仍保持9层：第0层起点、第8层 Boss，第1～7层按拓扑模板在1～4个节点间展开。当前共有“关隘再分流、双菱形、宽路绕行、狭道关口、交织山谷”五组模板，每组至少包含两次中途分岔和两次中途汇合。

第1、3、7层为普通战，第5层为精英战，因此任一路径连同 Boss 固定5场必战。第2层至少含事件与商人，第4层至少含事件、商人与物品，第6层至少含事件、补给与卡牌；空余节点由补给填充。起点仍提供三路选择，随后路线会收窄、再次分流或形成短支路，最后汇入 Boss。两处商人机会和最多两次袭商战得以保留。连线采用上下有序的比例映射，每个节点至少一进一出，不产生交叉“X”、死路或不可达节点。

五组模板及三地权重都保存在远征内容定义中，属于【原型暂定】。河源偏向关隘和狭道，石门偏向狭道和交织山谷，临泽偏向宽路与双菱形；同一套规则不把某条屏幕位置永久定义为安全或危险路线。

## 2. 确定性生成与旧档兼容

拓扑模板、节点排列、敌人、事件分别使用独立派生 Seed。V4 `map_signature` 包含拓扑模板 ID、节点类别、内容 ID、敌军阵营、层内位置、商队护卫、奖励类型以及全部边。奖励池内容变化不会重排地图拓扑；同一目标、Seed 和生成器版本必须复现同一签名。

每个目标仍保留完整 V2、V3 生成配置。活动 V2/V3 远征按原版本和签名重建，V4及更早的活动河源固定图继续使用 V1 与旧遭遇解析器。V4 不提升 Save 结构版本；玩家回城后的新远征才使用新拓扑。

## 3. 可见情报与斥候

V3/V4 的 `visible_nodes` 都把“类别可见”和“详情可见”分开。开局即公开全部节点类别：普通战只显示官兵/土匪，精英只显示强敌，事件统一显示“途中事件”，商人、补给、物品、卡牌与 Boss 显示自身类别。未来节点仍不可越级点击。

抵达节点后公开具体敌军或事件标题。斥候令牌揭示当前层之后两层的具体敌军名称和事件标题，但事件风险结果、卡牌候选和奖励细节仍不提前公开。风险结果在遭遇检查点创建时按 Seed 冻结，对 UI 输出前移除内部 `resolved_effects`。

## 4. Save V6 与长期民望

Campaign 新增 `popular_support_state`，新档从20开始并限制在0～100；Expedition 保存出发值、本趟待结算变化与投影值。事件条件读取投影民望。民望不修改战斗、收入、兵源、叛乱阈值或敌人强度。

`SettlementRequest.popular_support_delta` 与叛乱变化一起进入幂等最终结算。成功、撤退和失败均提交已发生的民望变化。事件把兵力或士气降至0时，远征立即进入失败待结算：武将记为重伤但不因非战斗事件永久死亡，未入库战利品丢失，民望与叛乱仍可提交。

Save 版本保持 V6，新档内容版本更新为 `0.7.2-m6-route-variety`。V5及更早存档迁移后初始民望为20；活动远征的待结算民望默认为0。

## 5. 36个事件的数据契约

`prototype_rogue_expeditions.json` 当前包含12个通用事件和河源、石门、临泽各8个地域事件，共36个。V3/V4 每张地图从“12通用 + 本地8个”的20个候选中无重复抽取3个。

每个事件必须有2～3个唯一 `choice_id`，并至少有一个无随机结果的安全选项。条件统一支持未入库资源、武将属性、临时物品和投影民望。随机选项按事件 Seed 固定为50/50；界面说明已知成本和可能结果范围，但不泄露本次被冻结的结果。银钱、粮食、兵源和军学仍进入未入库战利品。

事件选择、兵力/士气、民望/叛乱、路线完成和解析流水作为一个事务提交。选择前自动保存；选择后的自动保存失败时，协调器恢复选择前的完整 SaveEnvelope。

## 6. UI 与验证证据

地图画布按每层实际节点数自动等距布局，单点关隘居中、宽路最多展开四个节点；斜向分岔/汇合以铜色高亮，已走路线加粗。顶部常驻显示未入库战利品、物品栏、投影民望及本趟民望/叛乱变化；主城、目标页、事件页和最终结算页同样显示相应民望。事件结算反馈实际发生的兵力、士气、民望和叛乱变化。

scripts/ci/run_godot_test.sh godot res://tests/run_m6_ui_tests.gd /tmp/dynasty-rebellion-m6-04f-ui

M6-04F 最终结果：Rogue 专项2106通过、0失败；真实 UI 专项73通过、0失败；23套完整串行回归3930通过、0失败。严格扫描未发现 `SCRIPT ERROR`、`Parse Error`、`Invalid call`、`TEST FAIL:`、未处理异常或非白名单 `ERROR:`。

生成器测试覆盖三地各200个 Seed、五组拓扑、平面连线、分岔/汇合、V2/V3签名和V1/V2/V3活动恢复。真实 UI 测试覆盖全图类别预判、变宽/收窄路线、具体事件抵达和事件结算反馈。地图已以真实 Godot 图形窗口在1600×900和1280×720完成渲染复核，未发现裁切、节点重叠或不可达操作。

## 7. 后续边界

自动化只证明地图约束、事务、迁移和交互正确。路线选择是否有趣、36个事件是否足够丰富、风险收益是否合理、单局是否达到30～40分钟，以及民望是否值得扩展，仍由 M6-05 真人试玩决定。本批没有实现围剿、民望被动收益、事件专属战斗、装备、途中删牌或正式剧情演出。
