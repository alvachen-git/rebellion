# M5 存档迁移、备份与结算恢复说明

## 1. 本批范围

M5-07 将长期战役存档从“V1 增量补默认值”升级为显式 Save V2，并完成原子文件写入、最近备份、内容引用校验和跨军队/武将/势力消费者的结算最终化。正式主城存档页面、槽位选择画面和视觉反馈仍按玩家决定后置，本批只交付可由后续 UI 调用的领域与持久化接口。

## 2. Save V2 与顺序迁移

`SaveMigrationRegistry` 是唯一版本迁移入口。载入先解析原始 JSON，再按版本逐步调用迁移函数；当前注册 `v1 → v2`，未来版本继续追加独立步骤，禁止在解码器中堆叠字段分支。

V1 到 V2：

- 使用 `CampaignState.normalize()` 补齐 M5 军队、研究、武将、势力和最终化状态；
- 为旧待处理效果补齐三个消费者标记、零值分类兵损、旧兵损恢复记录和最终化标记；
- 增加 `applied_finalization_ids` 与 `finalization_history`；
- 保留原 `content_version`、时间戳和未知扩展字段作为来源审计；
- 迁移输入始终深拷贝，调用者持有的旧 DTO 不被修改。

未来版本会被明确拒绝；缺少版本、V1 根字段损坏或迁移后不满足完整 Save V2/CampaignState 契约的文件同样不能进入游戏状态。

## 3. 原子文件与最近备份

`SaveFileStore.save()` 的提交顺序固定为：

1. 深拷贝待保存 Envelope，写入调用者提供的确定性 `updated_at`；
2. 在内存中做完整 Save V2 校验与编码；
3. 写入同路径 `.tmp` 并刷新文件；
4. 重新读取 `.tmp`，执行 JSON 解码、迁移和完整状态校验；
5. 将已有正式档轮换为单份 `.bak`；
6. 将验证后的 `.tmp` 提升为正式档；若提升失败，则把刚轮换的备份恢复为正式档。

未提交的孤立 `.tmp` 永远不会参与载入。主档损坏、结构无效或内容 ID 失效时，`load()` 会尝试最近 `.bak`，并在返回值中标明 `source=backup`、`recovered=true` 及主档错误。载入不会静默覆盖损坏主档，是否重新保存交给后续 UI/流程显式决定。

## 4. 内容引用校验

`SaveContentReferenceValidator` 在提供当前 `ContentRegistry` 的载入路径中校验：

- 武将、核心/当前天赋及专属卡；
- 公共卡解锁与升级键；
- 领地实例；
- 待处理结算、结算流水和当前远征引用的远征 ID；
- 待处理效果中的武将必须仍存在于该战役武将名册，自创玩家占位允许不属于首轮内容目录。

错误包含字段位置和缺失稳定 ID。内容无效的主档也可以触发备份恢复，避免结构正确但引用已失效的存档进入运行态。

## 5. 结算最终化与中断恢复

`CampaignController.finalize_pending_settlement()` 以远征 `request_id` 为最终化事务 ID：

1. 要求军队兵损已经由新 DTO 分类扣除，或旧 DTO 已完成显式恢复；
2. 消费尚未完成的武将效果；
3. 若玩家角色死亡，由同一请求进入 Game Over，并明确跳过势力时间；否则消费尚未完成的势力效果；
4. 三个消费者都完成后设置 `long_term_effects_finalized=true`，写入最终化幂等 ID 和审计流水；
5. 任一消费者或完整状态校验失败，恢复最终化前的深拷贝状态。

因此，载入“武将已处理、势力未处理”等中断状态时，只执行缺失消费者，不重复经验、周期、领地、收入或恢复。相同最终化请求再次提交返回成功重复态，不修改状态。

## 6. 旧 DTO 兵损恢复边界

V1 旧远征 DTO 没有 `initial_troops` 和 `army_composition`，无法安全反推出步/弓/骑分类损失。迁移继续保留 `army_losses_applied=false`，最终化会返回 `requires_legacy_army_recovery=true`，不会猜测构成。

调用 `recover_legacy_army_losses()` 后：

- 三种军队库存保持不变；
- 待处理效果记录 `legacy_snapshot_unavailable`；
- 军队流水记录旧版本缺少出征快照的原因；
- 该恢复本身幂等，完成后允许其余长期效果继续结算。

这是旧开发档兼容策略，不是新存档的伤亡规则。所有 V2 新结算仍必须携带出征快照并真实扣除分类兵损；后续 UI 载入此类旧档时必须向玩家显示恢复说明。

## 7. 保存时点策略

底层继续固定三个手动槽和一个自动档。手动保存只允许 `main_city` 与 `expedition_map`；战斗中恢复方式仍为按 Seed 检查点重开当前战斗。自动保存事件明确为：

- `new_campaign`；
- `expedition_node_settled`；
- `expedition_final_settled`。

战斗回合本身不会触发完整状态自动保存。
