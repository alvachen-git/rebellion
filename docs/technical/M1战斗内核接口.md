# M1 战斗内核接口

## 状态

M1 Headless 战斗内核已实现。当前内容均为 `development_only` 测试定义，不代表 19 张正式原型卡的最终数值。

## CombatRequest

调用方传入：

- `battle_id`、可记录的整数 `seed`
- `player`：武将 ID、是否玩家角色、兵力/士气/攻防、开战时兵种构成
- `enemy`：相同战斗属性及技能池
- `deck`：稳定 Card ID 数组
- 可选 `starting_action_points` 与 `draw_count`

`setup()` 会校验必需字段、牌组引用和敌人技能；错误请求不会进入战斗状态。

## CombatController 命令

- `play_card(hand_index)`：验证阶段、费用与条件，随后按定义顺序解析效果。
- `card_availability(hand_index)`：返回 `ok` 和可直接展示给 UI 的失败原因。
- `preview_card_damage(hand_index)`：与真实伤害共用 `DamageCalculator`。
- `end_player_turn()`：弃置手牌、执行已公开 Intent、检查结果并开始下一回合。
- `retreat()`：生成独立的撤退结果，保证武将不死亡或重伤。
- `snapshot()`：返回 UI/测试可消费的深拷贝状态，不暴露可变领域对象。

## CombatResult

结果包含：

- `status`：victory / defeat / retreated
- `reason`：兵力归零、士气归零或主动撤退
- 回合数及双方剩余兵力/士气
- `general_died`、`general_injured`、`game_over`

CombatResult 不直接修改 CampaignState；远征层将在 M4 负责把它转换成跨战与结算变化。

## 随机与日志

- 牌堆、敌人 AI、士气溃败结果使用从同一战斗 Seed 派生的独立随机流。
- 改变牌组不会通过洗牌随机消耗影响敌方 Intent。
- 事件日志按递增 sequence 记录，可用于复现、UI 动画和后续统计。

## 已实现效果

DealDamage、GainArmor、ModifyMorale、DrawCards、GainActionPoint、ModifyDefense、ApplyStatus、RepeatAttack、ConsumeOwnMorale、ConditionalEffect、DealDamageFromArmor、ConvertArmorToDamage、RetaliateOnDamage、PrepareTaggedAttack、RestoreTroops。

## 已实现条件

兵种比例、双方士气阈值、自身兵力比例、当前护甲、本回合出牌/攻击牌数量、本回合敌方士气损失、敌方防御阈值和状态存在性。
