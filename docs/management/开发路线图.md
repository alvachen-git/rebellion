# 开发路线图

每个里程碑都以“可演示结果 + 自动化验收 + 决策记录”结束。未通过验收时不把未完成内容包装成下一阶段成果。

## M0：项目与架构确认【完成】

### 交付

- 确认引擎、首发平台、输入方式、目标分辨率和存档哲学。
- 建立正式工程骨架、内容目录、测试入口和 CI 基线。
- 固化 Definition、Runtime State、Result、Save DTO 的边界。
- 提供一份最小 Card/Effect/Condition 示例数据并通过加载校验。

### 验收门

- 工程可在开发机和无界面模式启动。
- 空测试套件/样例测试可重复运行并显式报告 0 失败。
- 规则层不依赖 UI；数据引用错误能在启动阶段被发现。

## M1：Headless 战斗内核【完成】

### 交付

- 兵力、士气、攻击、防御、护甲、行动力与伤害管线。
- 抽牌、弃牌、洗牌、耗尽、费用和出牌条件。
- 可组合 Effect/Condition、状态与回合事件。
- 敌人技能池、Intent 和规则/权重 AI。
- 胜利、兵力死亡、士气溃败、撤退与 CombatResult。
- 固定 Seed 调试入口和结构化战斗日志。

### 验收门

- 核心公式、边界与失败路径全部有测试。
- 相同输入和 Seed 得到相同事件序列与结果。
- Combat 不会直接修改 CampaignState。

## M2：最小战斗 UI【完成】

### 交付

- 双方武将、兵力、士气、攻击、防御、护甲和兵种构成。
- 手牌、费用、行动力、条件失败提示和预计实际伤害。
- 敌方 Intent、结束回合、撤退确认和战斗结果。

### 验收门

- 能从调试入口完成整场战斗和撤退流程。
- 不可用牌明确显示原因；预计值与实际结算一致。
- 至少两种目标分辨率无关键遮挡，真实鼠标交互通过。

## M3：首批战斗内容【框架完成，平衡债延期】

### 交付

- 约 19 张关键牌及其完整数据。
- 赵烈、周靖、韩月和各自初始牌组/天赋。
- 五种普通敌人、两种精英和严成 Boss。
- Boss 阶段与三种战略削弱的战斗侧接口。

### 验收门

- 三名武将使用固定 Seed 能展示三种明显不同的核心回合。
- 士气胜利和兵力胜利都能在合理 Build 下实现。
- 普通战大体落入 3～5 回合，精英 4～7 回合，Boss 6～10 回合；偏离项有统计和说明。

## M4：《攻取河源县》远征【领域框架完成】

### 交付

- 12～16 节点的 authored/seeded 地图。
- 三条前段战略路线、汇合精英、后段情报/补给/财富选择。
- 军械库、烽火台、粮仓对 Boss 的独立削弱。
- 跨战兵力/士气、临时 Buff、未入库战利品和不可回头规则。

### 验收门

- 成功、主动撤退和任务失败三条流程都可完整演示。
- 结算前长期资源不变化；撤退丢奖励但保留应保留的损失。
- 同 Seed 可复现完整路线与战斗链。

## M5：主城与长期成长【进行中：M5-01～05完成】

### 交付

- 整军、军学、武将、势力、出征基础界面。
- 四主资源、军队库存、补兵与基础兵种训练。
- 公共卡研究、解锁和不可逆二选一升级。
- 武将 Lv1～Lv6 基础成长、重伤/死亡。
- 河源县领地与势力周期收入。
- 版本化 Save/Load 与备份恢复。

### 验收门

- 不可逆升级在保存、载入和迁移后保持唯一。
- 永久死亡会移除专属体系；玩家死亡正确进入 Game Over。
- 其他城市没有独立建设系统或隐藏的提前扩展。

### 当前进度

- M5-01 已建立 CampaignState、银钱/粮草/兵员/军学四主资源、特殊资源分仓和旧 V1 存档增量兼容。
- CampaignController 已能一次性校验并幂等接收远征结算：只有成功可入库奖励，撤退/失败只保存应延续的损失结果。
- 军队、武将、研究和领地的实际长期修改尚未提前实现；它们通过待处理长期效果队列交给 M5-02～05 分批消费。
- M5-02 已建立步兵、弓兵、骑兵统一库存，支持数据配方驱动的补兵/训练事务，并按开战时兵种构成把远征伤亡真实扣回库存。
- 训练成本仍是集中配置的【原型暂定】参数，不作为平衡验收结论；正式主城 UI 按玩家要求留在 M5-06，不在领域批次中提前制作。
- M5-03 已接入16张公共牌的长期研究、特殊残篇门槛、幂等资源事务和永久二选一升级；武将专属牌不进入势力公共研究。
- 已选分支通过纯解析器生成战斗用卡牌副本，不修改共享内容定义；研究成本同样保持【原型暂定】，正式起始牌库与研究节奏留给闭环试玩决定。
- M5-04 已建立赵烈、周靖、韩月的长期 `GeneralInstance`、Lv1～Lv6 成长、单趟最多一级、重伤禁用/周期恢复、普通武将永久死亡和玩家角色 Game Over 事务。
- 成长经验、属性与恢复周期仍是集中配置的【原型暂定】参数；Lv3/Lv4/Lv6 只记录待内容设计里程碑，不提前虚构成长天赋或新增专属卡。自创角色保持不可出征占位。
- M5-05 已注册河源县领地内容，并实现首次占领、主城阶段推进、成功制势力周期、下一周期起生效的周期收入，以及与武将重伤恢复的原子事务。
- 河源县收入和周期时点保持【原型暂定】；撤退/失败推进时间、招贤刷新与世界阶段变化仍待 M6 流程验证或后续内容设计。其他城市没有独立经营状态。
- M5-07 已建立 Save V2 与集中式 V1 顺序迁移，保存经临时文件回读校验后替换正式档并保留一份最近备份；载入可对内容稳定 ID 做校验并从有效备份恢复。
- 军队、武将、势力消费者已由最终化事务收口，支持半结算续接、失败整笔回滚和 Game Over 中断恢复；旧 DTO 缺少出征快照时只允许有审计的显式兼容恢复，不伪造兵种构成。
- M6-01A 已建立无 UI `GameFlowCoordinator`、Save V3 长期 Loadout、战斗检查点、数据化河源县节点解析与严格恢复；成功路线可两阶段结算回城，完成补兵、研究、改牌组、手动保存并验证再次出征就绪。
- M6-01A 不改变 M5-05 的成功制周期和新领地延迟一期收入策略。节点奖励、初始化资源和属性换算仍为【原型暂定】，待正式 UI 接入后的首次完整试玩复核。

## M6：Vertical Slice 闭环

### 交付

- 主城整备到再次出征的完整流程。
- 一次成功和一次失败/撤退的完整体验。
- 首轮引导、反馈、结果面板和最小占位视听表现。

### 验收门

- 新存档可无调试命令跑完整闭环。
- 存档中断与恢复不产生资源复制、损失回滚或重复结算。
- 逐项回答设计文档第 26 节的 12 个验收问题，并记录证据。

### 当前进度

- M6-01A 已完成无 UI 成功闭环、撤退/失败/死亡分支和地图/战斗/待结算三阶段恢复，19组串行回归1647/0。
- M6-01B 已把正式主城、整备、河源县地图、现有战斗 UI 和最终结算接入 GameShell；20组串行回归1686/0，并完成1280×720图形化截图复核。
- M6-02 已完成玩家可见的成功、撤退、士气失败、永久死亡、Game Over 和旧档显式恢复验证；体验专项33/0，21组完整回归1719/0。
- M6-03A 已完成军议堂、15～25张共用公共基础牌组、武将专属牌自动合成、Save V4迁移与旧档恢复；专项69/0，22组完整回归1791/0，并完成军议堂和出征整备的1600×900、1280×720图形复核。
- M6-04 已把出征扩为河源、石门、临泽三目标，并完成9层Seed随机图、事件/商人/物品/途中卡牌、叛乱值、Save V5、旧活动河源v1兼容和通用UI；Rogue专项868/0，23组完整回归2678/0，三类新页面均完成1600×900与1280×720图形复核。
- M6-04E 已完成三条清晰主线、两处相邻换道、全图类别预判、斥候详情、长期民望、36事件库与Save V6；Rogue专项2092/0、UI专项74/0、23套完整回归3917/0，并完成1600×900与1280×720地图和事件面板图形复核。
- M6-04F 已把固定三线替换为V4分岔—汇合式拓扑：五套数据模板、中间层1～4节点、至少两次分流与两次汇合、无交叉X，并保留全图类别预判及V1～V3恢复；Rogue专项2106/0、UI专项73/0、23套完整回归3930/0，双分辨率图形复核通过。
- M6-05 现在可开始组织三目标 Rogue 真人试玩并逐项回答12个验收问题；自动化只证明流程、事务、恢复和交互正确，不证明路线感、风险收益、节奏、时长或永久奖励已经好玩。

## M7：测试与调优工具

### 交付

- 战斗调试面板、指定内容/Seed、回合日志和统计。
- Build × 敌人批量模拟与结果导出。
- 首轮平衡报告及建议调整，不擅自改动锁定规则。

### 验收门

- 关键平衡结论可通过内容版本、输入配置和 Seed 复现。
- 调优参数全部来自配置，代码中不存在为单次测试临时写死的数值。

## 建议执行顺序

先完成 M0 决策，然后严格按 M1 → M2 → M3 → M4 → M5 → M6 推进；M7 的日志与 Seed 基础在 M1 就开始建设，完整工具在闭环后集中补齐。每个里程碑可以拆为 1～2 周的小批次，但是否调整节奏以实际试玩结果为准。
