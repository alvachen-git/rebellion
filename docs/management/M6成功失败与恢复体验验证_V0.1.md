# M6 成功、失败与恢复体验验证 V0.1

## 1. 验证范围

本报告对应 M6-02，只确认玩家可见流程是否完整、后果是否与权威状态一致、存档是否可恢复。它不替代真人对“是否好玩、是否疲劳、风险是否合适”的主观试玩结论。

覆盖场景：

1. 新档成功完成河源县，回城成长并再次整备。
2. 战斗中主动撤退，确认未入库战利品丢失、真实兵损保留、武将生还。
3. 士气归零失败，确认武将重伤、领地不取得、势力周期不推进。
4. 兵力归零导致普通武将永久死亡，回城后武将不可再次出征。
5. 载入玩家角色死亡状态，进入独立 Game Over 页面。
6. 载入缺少长期 Loadout 的 Save V2，要求显式恢复并保存到手动槽；原自动档不被覆盖。

## 2. 玩家可见信息

失败终报按“原因 → 永久后果 → 确认动作”组织：

- 撤退：武将安全生还；未入库战利品全部丢失；兵损永久扣除。
- 士气失败：明确显示军心崩溃与重伤；不使用笼统的“战败”代替原因。
- 永久死亡：确认前直接显示阵亡武将、永久死亡、兵损、领地和周期后果。
- Game Over：由 `campaign_status=game_over` 进入独立终局，不由 UI 推测。
- 旧档恢复：列明会授予15张原型公共卡和三套20张牌组，并说明资源、成长与来源内容版本不变。

图形化复核在1280×720完成。永久死亡页的后果文字和唯一确认按钮没有越界；根据首张截图移除了重复失败提示，并把被容器拉宽的确认按钮收束为居中主行动。

## 3. 自动化证据

- `run_m6_ui_tests.gd`：成功闭环39通过、0失败。
- `run_m6_experience_tests.gd`：撤退、士气失败、永久死亡、Game Over、Save V2恢复及手动槽重载33通过、0失败。
- 21组串行全量回归：1719通过、0失败。
- 严格扫描：没有解析错误、无效调用、未处理异常、测试失败或非白名单 ERROR。

## 4. 已证明与未证明

已证明：

- 所有目标状态都能从正式主场景进入或恢复。
- 玩家确认前可以看到结果原因和长期后果。
- 玩家确认后，UI 展示与 Campaign/Expedition 权威状态一致。
- 旧档恢复是显式、可审计、幂等且不覆盖原自动档的操作。

尚未证明，必须留给 M6-03 真人试玩：

- 远征连续战斗是否疲劳。
- 战利品丢失的风险感是否足够或过强。
- 永久死亡是否会让玩家雪藏最强武将。
- 三条路线是否真的会因 Build 不同产生选择。
- 回城成长是否产生足够强的“再打一趟”动机。
- 12个验收问题中的战斗策略、Build爆发和节奏结论。

## 5. M6-03 建议试玩顺序

1. 新档使用赵烈走任意路线并完成成功闭环。
2. 第二档在获得至少一项战利品后主动撤退。
3. 使用测试档观察一次士气失败和一次永久死亡终报。
4. 逐项回答设计文档第26节12个问题；无法判断的项目记录为“证据不足”，不强行通过。
