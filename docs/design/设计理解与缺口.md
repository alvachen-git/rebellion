# 设计理解与缺口

## 1. 我对游戏的完整理解

这是一款“战役长期成长”和“单次节点远征”嵌套的卡牌策略游戏。长期层决定武将、军队库存、公共卡解锁及其不可逆升级、领地收入和主城阶段；远征层负责路线选择、连续兵力/士气、临时 Buff、军事据点和未入库战利品；战斗层是一名武将代表一整支军队的回合制卡牌战斗。

它的主要差异点不是 Roguelike 中途拿牌，而是玩家先在长期存档中养成一套势力军学，再把某位武将的天赋、专属卡、公共牌和兵种构成组合成 Build，带进约 30 分钟的高风险远征。胜利会增强长期 Build，失败可能丢失整趟收益、真实军队库存，甚至永久失去一名玩法体系完整的武将。

第一张远征《攻取河源县》同时承担玩法教学和 Build 检验：前半段三条路线分别削弱 Boss 的防御、援军或恢复能力；玩家应根据自己的 Build 选择最有价值的战略目标，而不是永远存在一条最优路线。

## 2. 三层闭环

### 战斗层 Combat

- 输入：武将战斗快照、军队构成、20 张左右的牌组、敌人定义、Seed、远征 Buff。
- 运行：抽牌/弃牌/耗尽、行动力、攻击/防御/护甲、士气条件、兵种门槛、敌人 Intent 与规则 AI。
- 输出：胜负原因、剩余兵力/士气、武将风险结果、伤亡、日志和统计；不直接写长期存档。

### 远征层 Expedition

- 输入：已完成的出征配置与目标远征定义。
- 运行：不可回头的节点路线、跨战连续兵力/士气、临时 Buff、未入库战利品、战略据点状态。
- 输出：成功结算、主动撤退或任务失败；负责组装需要交给战役层的结算请求。

### 战役层 Campaign/Main City

- 保存四种主资源、特殊资源、军队库存、武将成长/伤势/死亡、公共卡、永久升级分支、领地、周期和主城阶段。
- 负责整军、军学、武将、势力和出征整备。
- 只有远征成功才正式接收战利品；撤退或失败只接收允许保留的损失与状态变化。

## 3. 已锁定且实现不得改变的关键规则

- 玩家角色可出战、无继承制、死亡即 Game Over。
- 兵力归零时武将 100% 死亡；士气归零时 20% 死亡、80% 重伤。
- 主动撤退保证武将生还，但远征立即失败、未入库奖励全失，既有兵力损失保留。
- 远征没有安全撤离节点；完成任务才可把战利品入库。
- 单名武将代表整支军队；兵种只影响初始值与卡牌资格，不作为独立场上单位。
- 卡牌兵种资格按开战时构成锁定。
- 普通兵力伤害不降低士气；士气不提供自动全局属性加成。
- 公共牌属于势力，专属牌与天赋随对应武将死亡永久消失。
- 公共卡升级是一次重大二选一，本局永久锁定且不可重置。
- Build 在整个存档中形成，远征途中不进行主牌组的拿牌/删牌式重构。
- 其他城市仅作为资产和收益来源，不逐城建设经营。
- 敌人使用技能池、公开 Intent 与规则 AI，不复制玩家完整抽牌系统，也不读取未来手牌。

## 4. 可配置、可测试调整的内容

- 伤害、递减防御、护甲清除时点及撤退附加损失。
- 行动力、抽牌数、牌组规模、稀有度复制上限。
- 武将、敌人、Boss、资源收入、恢复周期与升级节奏的具体数值。
- 地图节点数量、战斗数量和各类节点权重。
- AI 技能权重和条件阈值。

这些内容应落在数据定义或统一平衡配置中，以便在不改代码的情况下跑同 Seed 对比。

## 5. 目前真正缺少的制作输入

### M1 前必须确认

1. 最终使用的游戏引擎与首发平台。
2. 永久死亡是否采用铁人式自动存档，还是允许玩家读旧档规避死亡。
3. 玩家角色在 Vertical Slice 中是可完整亲征，还是只做主城占位并先用三名测试武将验证战斗。

### M2 前必须确认

1. 横屏目标分辨率、鼠标/键盘与手柄/触屏的首要输入方式。
2. 战斗画面的信息密度和视觉方向：偏桌面卡牌、战场军阵，或人物立绘主导。

### M3 前必须补齐

1. 19 张首批卡牌的费用、标签、数值、条件、效果、升级分支和文本。
2. 三名武将首批实际入牌的专属卡组合及其初始牌组。
3. 五普通敌人、两精英和 Boss 的完整技能数据与 Intent 规则。

### M4/M5 前可后置确认

1. 河源县地图采用完全固定布局，还是“固定战略骨架 + Seed 随机普通节点”。
2. 士气溃败后的敌将是死亡、被俘、逃走，还是只作为普通胜利标签处理。
3. 玩家士气溃败并重伤后，幸存部队如何返还势力库存；主动撤退是否推进势力周期。
4. 首轮研究、补兵、兵种训练和领地收入的平衡表。

### M5-04 后仍需内容设计

1. 赵烈、周靖、韩月在 Lv3 与 Lv6 的两组实际天赋二选一，以及每个分支的效果与文案。
2. 三名武将在 Lv4 解锁的额外专属卡；当前各自只有 M3 已实现的一张起始专属卡。
3. 经验阈值、不同远征结果经验、Lv2/Lv5 属性增量与重伤恢复周期的最终平衡值；代码中的当前值仅为 `prototype_temporary`。

### M5-05 后仍需流程复核

1. 完整战役中主动撤退与失败是否推进势力周期；Vertical Slice 当前为防止撤退刷收入而采用成功才推进。
2. 新占领领地应在取得周期立即发放一次收入，还是从下一周期开始；当前采用下一周期开始。
3. 招贤刷新与世界阶段变化的实际规则和内容；当前只保留明确的 deferred 边界。

## 6. 当前判断

设计已经足够支持项目立项和 M0/M1 架构工作，核心循环没有结构性矛盾。当前不宜直接批量制作 UI 或 19 张卡牌内容，因为引擎、平台、存档态度和卡牌明细尚未锁定。最值得优先验证的是：纯战斗内核能否让三种 Build 出现明显的“准备—启动—爆发”，以及士气胜利能否和兵力胜利同样有价值。
